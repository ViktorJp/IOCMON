            @twiglets for this suggestion!

            only change items when deemed necessary, and won't be the cause of creating additional alerts.
          - PATCH: Added the proof-of-concept toggles to yes/no items in the menus, greatly inspired by
            Wireless Report by @JB_1366! Let me know if they visually help distinguish the overall state

          - PATCH: Firmed up more governance in the config menus when a primary item is disabled, that the
            dependent items under it are now grayed out and unavailable to change. If previous values were
            entered, those items will stay until the primary item is enabled again.
          - PATCH: Fixed 9.5.2 and realigned the menu settings per @Visortgw's OCD request. ;)
          - PATCH: Reorganized the main Configuration menu and added section headers, much like what you
            would see in BACKUPMON.
          - PATCH: Added a new menu item 9.4.3 "Critical-path MOD alert mode (.ssh/startup-scripts/.conf.add)"
            which allows you to choose how you would like to be alerted when critical files are modified.
            You can choose between "Upon File Modification", when a file is touched, modified, may not
            change its contents or it may have content changes, or "Upon File Hash Mismatch", when a file
            actually changes in contents. Thanks to @XIII for the great suggestion.
          - PATCH: Added /jffs/.ssh to the critical file paths to watch.
          - PATCH: Revamped the DNS Exceptions menu (9.2.2) to make the experience dealing with this ever-

            to the IoC domain entry to be added.
          - PATCH: Think I finally found a fix to the screen corruption issue when rejoining a brand new
            screen session after a fresh reboot where IOCMON started on its own. This would redraw the timer
